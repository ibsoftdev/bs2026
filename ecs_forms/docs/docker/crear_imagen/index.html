Oracle Forms & Reports 14.1.2 Crear la imagen image_forms_14.1.2 JDK 17 · FMW Infrastructure · Oracle Linux 9

Imagen Docker lista para WLS_FORMS, WLS_REPORTS y el Configuration Wizard

Visión general

Esta guía describe los pasos para construir la imagen Docker image_forms_14.1.2, que incluye JDK 17, Fusion Middleware Infrastructure 14.1.2 y Forms & Reports 14.1.2 sobre Oracle Linux 9. También incorpora, desde el build, las dependencias de sistema y las librerías compartidas necesarias para ejecutar WLS_FORMS y el motor de WLS_REPORTS.

Revisión r2 · motor de Reports La imagen r1 no incluía las librerías Motif/X11 que necesita el motor de Reports (librw.so, librwu.so → libXm.so.4). Con r1, WLS_REPORTS arranca, pero al ejecutar un reporte falla con DFW-99998 UnsatisfiedLinkError: librwu.so: libXm.so.4 y la petición queda colgada. El Dockerfile.wls actual ya instala esos paquetes (punto 4.e) y verifica librw*.so durante el build. Para imágenes ya construidas existe Dockerfile.r2 (punto 7.a).
Archivo de referencia La construcción se realiza con el Dockerfile Dockerfile.wls (copia local en esta carpeta). El original se encuentra en weblogic/wl_image/Dockerfile.wls.

Dependencias resueltas en la imagen, no en cada contenedor.

1 Requisitos previos

  • Docker instalado (con soporte de docker buildx).
  • Espacio en disco suficiente (varios GB para instaladores y capas de imagen).
  • Acceso a los repositorios yum de Oracle Linux 9 durante el build (para libaio, gcc, etc.), incluido el repositorio EPEL de Oracle (ol9_developer_EPEL), del que proviene x11vnc.
  • Los siguientes instaladores en el directorio de build (wl_image/):

2 Preparar el contexto de build

El build debe ejecutarse desde el directorio donde están los instaladores y el Dockerfile (típicamente weblogic/wl_image/): 

cd /home/ibsoft/trabajo/tools/Descargas/weblogic/wl_image

ls -lh jdk-17_linux-x64_bin.tar.gz \

       fmw_14.1.2.0.0_fr_linux64.bin \
       Dockerfile.wls
Importante Los nombres de los instaladores deben coincidir exactamente con las variables JAVA_INSTALLER, INFRA_INSTALLER y FR_INSTALLER definidas en Dockerfile.wls.

3 Etapas del Dockerfile

Dockerfile.wls usa un build multi-stage: una etapa instala y compila todo el software, y la imagen final parte de un Oracle Linux limpio y copia solo lo necesario.

Stage 1 · builder oraclelinux:9→ Paquetes base→ JDK 17→ FMW Infrastructure→ Forms & Reports→ genshlib (.so) Stage 2 · imagen final oraclelinux:9→ Runtime + Motif/X11→ GUI Wizard→ COPY desde builder→ ldd librw*.so→ image_forms_14.1.2

a Stage 1 · Builder oraclelinux:9 as builder

  1. Instala paquetes del sistema: unzip, tar, wget, openssl, glibc, libaio, libnsl, gcc, make, binutils, nano y net-tools.
  2. Crea el usuario/grupo oracle (uid/gid 1000) y los directorios /u01/jdk, /u01/oracle y /u01/app/oraInventory.
  3. Copia los tres instaladores a /tmp/.
  4. Genera archivos de respuesta silenciosos: infra.rsp (Infrastructure), fr.rsp (Forms and Reports) y oraInst.loc (inventario Oracle).
  5. Como usuario oracle:
    • Instala el JDK 17 en /u01/jdk.
    • Instala Fusion Middleware Infrastructure (modo silent).
    • Instala Forms and Reports Deployment (modo silent).
    • Genera las librerías compartidas de Forms (.so) con genshlib (ver punto 4).

b Stage 2 · Imagen final oraclelinux:9

  1. Instala paquetes de runtime: libaio, libnsl (Forms), gcc, make, binutils (toolchain para regenerar librerías compartidas), nano y net-tools (utilitarios de administración), motif, libX11, libXext, libXt y libXp (motor de Reports, ver punto 4.e).
  2. Instala las librerías gráficas del Configuration Wizard: Xvfb, x11vnc (desde EPEL), xauth, xhost, dbus-x11, librerías X11/fuentes para Java y, si están disponibles, twm y utilidades X11 (ver punto 5).
  3. Define PATH y LD_LIBRARY_PATH apuntando a $ORACLE_HOME.
  4. Copia desde el builder: JAVA_HOME, ORACLE_HOME (incluye los .so generados) y el inventario Oracle.
  5. Verifica con ldd que $ORACLE_HOME/lib/librw*.so no tenga dependencias not found; si falta alguna, el build falla.
  6. Recrea el usuario oracle y ajusta permisos sobre /u01.
  7. Define WORKDIR en /u01/oracle y deja la imagen lista para crear el dominio y arrancar servidores (fuera del build).
Variables de entorno en la imagen final
JAVA_HOME=/u01/jdk
ORACLE_HOME=/u01/oracle
DOMAIN_HOME=/u01/oracle/user_projects/domains/base_domain
LD_LIBRARY_PATH=/u01/oracle/lib
PATH incluye /u01/oracle/bin y /u01/jdk/bin

4 Librerías requeridas por WLS_FORMS y Reports

Tras una instalación silenciosa de Forms, $ORACLE_HOME/lib suele contener solo archivos estáticos (.a). El proceso de Forms (frmweb), usado por WLS_FORMS, necesita las equivalentes dinámicas (.so / .so.0). Si faltan, el managed server no puede crear el proceso runtime de Forms.

Estas dependencias deben quedar resueltas en la imagen No en cada contenedor después del despliegue. El Dockerfile.wls las incorpora en el Stage 1 (toolchain + genshlib) y en el Stage 2 (libaio, libnsl, gcc, make, nano, net-tools).

a Paquete de sistema libaio

libaio es una dependencia nativa de las librerías Oracle. Sin ella, herramientas como sqlplus y componentes de Forms fallan al cargar. Se instala:

  • En el builder, junto con el resto de paquetes base.
  • En la imagen final, porque el Stage 2 parte de oraclelinux:9 limpio (no hereda los paquetes del builder).

b Toolchain de compilación gcc · make · binutils

genshlib (incluido en $ORACLE_HOME/bin) enlaza cada .a para producir el .so.0 correspondiente. Para ello requiere compilador y linker.

  • Se instalan en el Stage 1 (builder) para generar las librerías .so durante el build.
  • También se dejan en la imagen final, de modo que se puedan regenerar o ampliar librerías compartidas de Forms sin reconstruir toda la imagen.

c Librerías compartidas con genshlib 16 librerías en $ORACLE_HOME/lib

Cada librería se genera como .so.0; libiplsn además recibe un symlink .so.

libiplsnlibibfrmwlibiffwlibifcw libijcwlibipfwlibimffrmwlibiwfw libiwcwlibitwlibicwlibsosdw libixwlibiicwlibiiiwlibiqw

Procedimiento equivalente (ya automatizado en el Dockerfile):

export ORACLE_HOME=/u01/oracle
export PATH=$ORACLE_HOME/bin:$PATH
export LD_LIBRARY_PATH=$ORACLE_HOME/lib:$LD_LIBRARY_PATH
cd $ORACLE_HOME/lib

for lib in \
  libiplsn libibfrmw libiffw libifcw libijcw libipfw libimffrmw \
  libiwfw libiwcw libitw libicw libsosdw libixw libiicw libiiiw libiqw
do
  echo "=== Generando ${lib}.so.0 ==="
  if [ ! -f "${lib}.a" ]; then
    echo "ERROR: falta ${lib}.a"
    exit 1
  fi
  rm -f "${lib}.so" "${lib}.so.0"
  $ORACLE_HOME/bin/genshlib "${ORACLE_HOME}/lib/${lib}.so.0"
done

# Verificación
ldd $ORACLE_HOME/bin/frmweb | grep "not found" || echo "OK: sin dependencias faltantes"
Resultado esperado Cada librería aparece como .so.0 con un symlink .so, y ldd $ORACLE_HOME/bin/frmweb no reporta dependencias not found.
Nota Durante el enlace de libsosdw puede aparecer un warning de ld sobre el uso de tempnam. Es esperado y no impide la generación de la librería.

d Utilitarios de administración nano · net-tools

Además de las dependencias de Forms, la imagen incluye utilitarios prácticos para administrar el contenedor:

PaqueteUso
nanoEditor de texto ligero para ajustar archivos de configuración dentro del contenedor (default.env, scripts, etc.).
net-toolsHerramientas de red clásicas (ifconfig, netstat, route) útiles para diagnosticar conectividad entre contenedores y puertos de WebLogic / Forms.

Se instalan tanto en el builder como en la imagen final, para no tener que ejecutar yum install después de crear el contenedor.

e Librerías Motif/X11 del motor de Reports librw.so · librwu.so

El motor de Reports (rwEng), que WLS_REPORTS lanza con $DOMAIN_HOME/reports/bin/rwengine.sh, carga las librerías nativas $ORACLE_HOME/lib/librw.so y librwu.so. Estas dependen de Motif y X11, aunque el motor no muestre ninguna interfaz gráfica. Oracle Linux 9 mínimo no las trae.

PaqueteLibrería que aporta
motiflibXm.so.4
libX11libX11.so.6
libXextlibXext.so.6
libXtlibXt.so.6
libXplibXp.so.6

Síntoma cuando faltan (log de WLS_REPORTS / incidente ADR):

DFW-99998 ... java.lang.UnsatisfiedLinkError: /u01/oracle/lib/librwu.so: libXm.so.4: cannot open shared object file

Instrucción en el Stage 2 de Dockerfile.wls (junto con los paquetes de runtime) y verificación posterior al COPY: 

RUN dnf install -y libaio libnsl gcc make binutils nano net-tools \
                   motif libX11 libXext libXt libXp && \
    dnf clean all
...
RUN missing=$(for f in ${ORACLE_HOME}/lib/librw*.so; do ldd "$f" | grep 'not found'; done | sort -u) && \
    if [ -n "$missing" ]; then echo "Missing libraries for Reports:"; echo "$missing"; exit 1; fi && \
    echo "OK: librw*.so has no missing shared library dependencies"
Nota Las fuentes que el motor usa para PDF se buscan en $DOMAIN_HOME/reports/fonts (REPORTS_FONT_DIRECTORY), que forma parte del dominio y no de la imagen. Ver la guía de creación del dominio, paso "Completar Reports".

5 Librerías gráficas para el Configuration Wizard

El dominio se crea con el Configuration Wizard, que solo se ejecuta en modo gráfico. Dentro de un contenedor no hay pantalla, así que se usa un display virtual (Xvfb) y se expone por VNC (x11vnc) para verlo desde el host. Antes, estos paquetes se instalaban en cada contenedor con install-gui-packages.sh (Paso 0.6 de crear-dominio) y se perdían al recrearlo. Ahora quedan incluidos en la imagen.

PaqueteFunciónObligatorio
xorg-x11-server-XvfbServidor X virtual en memoria (display :99) donde se dibuja el Wizard.Sí
x11vncServidor VNC que publica el display virtual en el puerto 5900 (mapeado a 5902 en el host). Proviene de EPEL.Sí
xorg-x11-xauth, xhostAutenticación y control de acceso X11, necesarios para que Java AWT se conecte al display.Sí
dbus-x11Bus de sesión que requieren algunas aplicaciones gráficas Java.Sí
libXext, libXrender, libXtst, libXi, fontconfig, dejavu-sans-fontsLibrerías X11 y fuentes que usa la interfaz Swing del Wizard; sin ellas la ventana puede no abrir o mostrarse sin texto.Sí
xorg-x11-twm, xorg-x11-xinitGestor de ventanas básico y utilidades de arranque de X. Mejoran el manejo de diálogos del Wizard.Opcional
xorg-x11-utils, xorg-x11-server-utilsUtilidades X11 de diagnóstico.Opcional

Los opcionales se instalan solo si están disponibles. Instrucción equivalente en el Stage 2 de Dockerfile.wls: 

RUN dnf install -y oracle-epel-release-el9 && \
    dnf config-manager --enable ol9_developer_EPEL && \
    dnf install -y xorg-x11-server-Xvfb x11vnc xorg-x11-xauth xhost dbus-x11 \
                   libXext libXrender libXtst libXi fontconfig dejavu-sans-fonts && \
    dnf install -y --setopt=strict=0 xorg-x11-twm xorg-x11-xinit xorg-x11-utils xorg-x11-server-utils && \
    command -v Xvfb && command -v x11vnc && \
    dnf clean all
Comportamiento del build Los paquetes obligatorios se instalan en modo estricto (si alguno falta, el build falla). Los opcionales usan --setopt=strict=0, que omite los que no existan en los repositorios de Oracle Linux 9 sin detener el build. Al final se verifica que Xvfb y x11vnc estén disponibles.
Qué no incluye la imagen Solo se instalan los paquetes. El entorno gráfico (Xvfb, twm, x11vnc) se inicia cuando se necesita, con setup-gui.sh (Paso 0.7 de la guía de creación del dominio). Con la imagen nueva, el Paso 0.6 (install-gui-packages.sh) queda como verificación: el script detecta que los paquetes ya existen y no reinstala nada.

6 Construir la imagen

Desde el directorio wl_image/, ejecutar:

sudo docker buildx build -f Dockerfile.wls -t forms_ol9:14.1.2 .

Equivalente con el tag final directamente:

sudo docker buildx build -f Dockerfile.wls -t image_forms_14.1.2 .
Tag intermedio El comando documentado en ComandosDockers.txt usa el tag intermedio forms_ol9:14.1.2. En el siguiente paso se etiqueta (o se retaguea) como image_forms_14.1.2, que es el nombre usado por los contenedores y docker-compose.

7 Etiquetar como image_forms_14.1.2

Si el build se hizo con el tag forms_ol9:14.1.2:

sudo docker tag forms_ol9:14.1.2 image_forms_14.1.2
# Opcional, con tag de versión/revisión:
sudo docker tag forms_ol9:14.1.2 image_forms_14.1.2:r2
Revisión Una imagen construida con el Dockerfile.wls actual ya equivale a r2 (incluye las librerías del motor de Reports). Para AWS se sube a ECR con ese tag; ver la guía de ECR/ECS.

a Actualizar una imagen existente Dockerfile.r2

Si ya existe image_forms_14.1.2:r1 (construida antes de este cambio), no hace falta reconstruir todo: Dockerfile.r2 parte de ella y agrega solo los paquetes del punto 4.e, con la misma verificación de librw*.so. 

docker build -f Dockerfile.r2 \
  --build-arg BASE_IMAGE=image_forms_14.1.2:r1 \
  --build-arg RUN_USER=$(docker inspect -f '{{.Config.User}}' image_forms_14.1.2:r1) \
  -t image_forms_14.1.2:r2 .
Atención El punto final (.) es el contexto de build y es obligatorio; sin él, Docker responde "docker build" requires exactly 1 argument.

8 Verificar la imagen

Comprobación de variables de entorno, paquetes del sistema, librerías gráficas, librerías de Forms y dependencias nativas de Reports en un contenedor efímero: 

sudo docker images | grep -E 'image_forms_14.1.2|forms_ol9'

sudo docker run --rm --user=oracle --entrypoint /bin/bash image_forms_14.1.2 -c '
  echo "JAVA_HOME=$JAVA_HOME"
  echo "ORACLE_HOME=$ORACLE_HOME"
  echo "LD_LIBRARY_PATH=$LD_LIBRARY_PATH"
  $JAVA_HOME/bin/java -version
  # Paquetes de sistema
  ldconfig -p 2>/dev/null | grep libaio || ls /usr/lib64/libaio.so* 2>/dev/null
  gcc --version | head -1
  make --version | head -1
  nano --version | head -1
  ifconfig --version 2>&1 | head -1 || which ifconfig netstat
  # Librerías gráficas del Configuration Wizard
  for cmd in Xvfb x11vnc xauth xhost; do
    command -v $cmd || echo "FALTA: $cmd"
  done
  command -v twm || echo "twm no instalado (opcional)"
  # Librerías Forms generadas
  for lib in libiplsn libibfrmw libiffw libifcw libijcw libipfw libimffrmw \
             libiwfw libiwcw libitw libicw libsosdw libixw libiicw libiiiw libiqw; do
    ls $ORACLE_HOME/lib/${lib}.so* 2>/dev/null || echo "FALTA: $lib"
  done
  ldd $ORACLE_HOME/bin/frmweb | grep "not found" || echo "OK: frmweb sin dependencias faltantes"
  # Librerías nativas del motor de Reports (Motif/X11)
  for f in $ORACLE_HOME/lib/librw*.so; do ldd "$f" | grep "not found"; done | sort -u | grep . \
    || echo "OK: librw*.so sin dependencias faltantes"
'
Imagen lista Si aparecen las 16 librerías .so; están disponibles libaio, gcc, make, nano y net-tools; están Xvfb, x11vnc, xauth y xhost; y ni frmweb ni librw*.so reportan dependencias faltantes, la imagen queda lista para crear el dominio y ejecutar WLS_FORMS y WLS_REPORTS.

10 Contenido completo de Dockerfile.wls

Archivo ./Dockerfile.wls (copia en esta carpeta). Fuente original: weblogic/wl_image/Dockerfile.wls.
Dockerfile.wls Stage 1 builder + Stage 2 imagen final 
# ====================================================================
# STAGE 1: BUILDER - Handles installation of WLS, Forms, and JDK
# ====================================================================
FROM oraclelinux:9 as builder

# --- Environment Variables ---
ENV JAVA_HOME=/u01/jdk \
    ORACLE_HOME=/u01/oracle \
    DOMAIN_HOME=/u01/oracle/user_projects/domains/base_domain \
    INFRA_INSTALLER=fmw_14.1.2.0.0_infrastructure.jar \
    FR_INSTALLER=fmw_14.1.2.0.0_fr_linux64.bin \
    JAVA_INSTALLER=jdk-17_linux-x64_bin.tar.gz

# --- Setup Prerequisites (Root Operations) ---
USER root

# Install required system packages and dependencies
# - libaio / libnsl: runtime deps for Forms / Oracle client tools
# - gcc / make / binutils: required to generate Forms shared libraries (.so) with genshlib
# - nano / net-tools: operational utilities used during image and container administration
RUN dnf install -y unzip tar wget openssl glibc libaio libnsl gcc make binutils nano net-tools && \
    dnf clean all

# Create the user/group, installation directories, and Inventory directory
RUN groupadd -g 1000 oracle && useradd -u 1000 -g oracle -d /u01/oracle -s /bin/bash oracle && \
    mkdir -p ${JAVA_HOME} && \
    mkdir -p ${ORACLE_HOME} && \
    mkdir -p /u01/app/oraInventory && \
    chown -R oracle:oracle /u01 && \
    chown -R oracle:oracle /u01/app/oraInventory

# --- Copy Installers and Create Response Files ---
COPY ./${JAVA_INSTALLER} /tmp/
COPY ./${INFRA_INSTALLER} /tmp/
COPY ./${FR_INSTALLER} /tmp/

# Create silent response file for Infrastructure (infra.rsp)
RUN echo "[ENGINE]" > /tmp/infra.rsp && \
    echo "Response File Version=1.0.0.0.0" >> /tmp/infra.rsp && \
    echo "[GENERIC]" >> /tmp/infra.rsp && \
    echo "ORACLE_HOME=${ORACLE_HOME}" >> /tmp/infra.rsp && \
    echo "INSTALL_TYPE=Fusion Middleware Infrastructure" >> /tmp/infra.rsp && \
    echo "DECLINE_SECURITY_UPDATES=true" >> /tmp/infra.rsp && \
    echo "SECURITY_UPDATES_VIA_MYORACLESUPPORT=false" >> /tmp/infra.rsp && \
    echo "UNIX_GROUP_NAME=oracle" >> /tmp/infra.rsp

# Create silent response file for Forms and Reports (fr.rsp)
# Using the confirmed install type and required Oracle Inventory location file (/tmp/oraInst.loc)
RUN echo "[ENGINE]" > /tmp/fr.rsp && \
    echo "Response File Version=1.0.0.0.0" >> /tmp/fr.rsp && \
    echo "[GENERIC]" >> /tmp/fr.rsp && \
    echo "ORACLE_HOME=${ORACLE_HOME}" >> /tmp/fr.rsp && \
    echo "INSTALL_TYPE=Forms and Reports Deployment" >> /tmp/fr.rsp && \
    echo "DECLINE_SECURITY_UPDATES=true" >> /tmp/fr.rsp && \
    echo "SECURITY_UPDATES_VIA_MYORACLESUPPORT=false" >> /tmp/fr.rsp && \
    echo "UNIX_GROUP_NAME=oracle" >> /tmp/fr.rsp && \
    echo "inventory_loc=/u01/app/oraInventory" > /tmp/oraInst.loc && \
    echo "inst_group=oracle" >> /tmp/oraInst.loc

# Ensure installer files are owned by oracle:
RUN chown -R oracle:oracle /tmp/*.tar.gz && \
    chown -R oracle:oracle /tmp/*.jar && \
    chown -R oracle:oracle /tmp/*.bin && \
    chown -R oracle:oracle /tmp/*.rsp && \
    chown -R oracle:oracle /tmp/oraInst.loc
    

# --- Installation Steps (Run as 'oracle' user) ---
USER oracle

# 1. Install JDK
RUN tar -xzf /tmp/${JAVA_INSTALLER} -C ${JAVA_HOME} --strip-components=1

# Ensure ORACLE_HOME is clean before the installer runs
RUN mkdir -p ${ORACLE_HOME} && \
    rm -rf ${ORACLE_HOME}/* && \
    rm -rf ${ORACLE_HOME}/.[!.]*



# 2. Install Fusion Middleware Infrastructure (WLS + EM)
RUN export PATH=$JAVA_HOME/bin:$PATH && \
    java -jar /tmp/${INFRA_INSTALLER} -silent -responseFile /tmp/infra.rsp -ignoreSysPrereqs -invPtrLoc /tmp/oraInst.loc

# 3. Install Forms and Reports (Dependencies are now met)
# Note: Infrastructure is installed, satisfying the WLS/EM prerequisite.
RUN chmod +x /tmp/${FR_INSTALLER} && \
    /tmp/${FR_INSTALLER} -silent -responseFile /tmp/fr.rsp -ignoreSysPrereqs -invPtrLoc /tmp/oraInst.loc

# 4. Generate Forms shared libraries (.so) required by WLS_FORMS / frmweb
# The silent install leaves only static archives (.a) under $ORACLE_HOME/lib.
# genshlib builds the corresponding shared objects used at runtime.
ENV PATH=${ORACLE_HOME}/bin:${PATH} \
    LD_LIBRARY_PATH=${ORACLE_HOME}/lib

RUN cd ${ORACLE_HOME}/lib && \
    for lib in \
      libiplsn libibfrmw libiffw libifcw libijcw libipfw libimffrmw \
      libiwfw libiwcw libitw libicw libsosdw libixw libiicw libiiiw libiqw \
    ; do \
      echo "=== Generating ${lib}.so.0 ==="; \
      if [ ! -f "${lib}.a" ]; then \
        echo "ERROR: missing ${lib}.a"; \
        exit 1; \
      fi; \
      rm -f "${lib}.so" "${lib}.so.0"; \
      ${ORACLE_HOME}/bin/genshlib "${ORACLE_HOME}/lib/${lib}.so.0"; \
    done && \
    for lib in \
      libiplsn libibfrmw libiffw libifcw libijcw libipfw libimffrmw \
      libiwfw libiwcw libitw libicw libsosdw libixw libiicw libiiiw libiqw \
    ; do \
      test -e "${ORACLE_HOME}/lib/${lib}.so.0" || (echo "MISSING after genshlib: $lib" && exit 1); \
    done && \
    ldd ${ORACLE_HOME}/bin/frmweb | grep "not found" && exit 1 || echo "OK: frmweb has no missing shared library dependencies"


# ====================================================================
# STAGE 2: FINAL - Creates a clean, runtime-ready image
# ====================================================================
FROM oraclelinux:9

# Set runtime environment variables
ENV JAVA_HOME=/u01/jdk \
    ORACLE_HOME=/u01/oracle \
    DOMAIN_HOME=/u01/oracle/user_projects/domains/base_domain \
    PATH=/u01/oracle/bin:/u01/jdk/bin:${PATH} \
    LD_LIBRARY_PATH=/u01/oracle/lib

# Runtime OS packages:
# - libaio / libnsl: required by Oracle Forms native libraries
# - gcc / make / binutils: keep toolchain available for genshlib / Forms shared libs
# - nano / net-tools: operational utilities (editor, ifconfig/netstat)
# - motif / libX11 / libXext / libXt / libXp: required by Reports engine (librw.so, librwu.so -> libXm.so.4)
USER root
RUN dnf install -y libaio libnsl gcc make binutils nano net-tools \
                   motif libX11 libXext libXt libXp && \
    dnf clean all

# GUI packages for the Configuration Wizard (Xvfb display + VNC access)
# - Xvfb: virtual X display (:99); x11vnc (EPEL): exposes the display on port 5900
# - xauth / xhost / dbus-x11: X11 authentication and session bus for Java AWT/Swing
# - libX* / fontconfig / dejavu fonts: required by the Java GUI of the wizard
# - twm / xinit / X11 utils: optional window manager and utilities (installed if available)
