WLS_REPORTS y Colas en un contenedor, mismo dominio EFS

Visión general

Esta guía crea el contenedor WLS_REPORTS-Colas (servicio wls_reports-ec2) en el cluster forms-reports-ec2, en una instancia EC2 propia. El contenedor arranca WLS_REPORTS con startReports_EC2.sh: espera el Admin en weblogic-admin.forms.local:7001 y no reescribe config.xml (el Admin ya está arriba). Las colas (Pro*C / CARC00100) corren aquí y llaman a rwservlet en el mismo contenedor.

Requiere AdminServer-WLS_FORMS en RUNNING. Misma imagen ECR y mismo EFS.

Segundo contenedor EC2; el Admin vive en el primero.

1 Crear la instancia EC2

Segunda instancia: host Docker de la tarea Reports. No se monta EFS en el asistente de EC2: el EFS lo monta la task definition.

1.1 · De dónde sale la AMI (imprescindible)

La misma ruta que en AdminServer-WLS_FORMS 1.1: Parameter Store público → ID de AMI → Launch from AMI.

  1. Systems Manager → Parameter Store.
  2. Marca Públicos.
  3. Abre /aws/service/ecs/optimized-ami/amazon-linux-2023/recommended/image_id
  4. Copia el ami-….
  5. EC2 → Images → AMIs → Public images → pega el ID.
  6. Selecciona al2023-ami-ecs-hvm-2023.0.… → Launch instance from AMI.
No uses otra imagen Amazon Linux “normal”, Ubuntu o Marketplace no traen el agente ECS. La instancia no aparece en Infraestructura.

3.3 · Scripts en EFS

El orquestador startReports_EC2.sh llama a startWLSReports.sh (en scripts/reports/ o junto al orquestador). El volumen efs-scripts monta la raíz …/domain_forms/scripts en /u01/oracle/scripts. Deben existir:

  • /u01/oracle/scripts/startReports_EC2.sh
  • /u01/oracle/scripts/reports/startWLSReports.sh
  • /u01/oracle/scripts/colas/set_batch_env.sh (colas / CARC00100)

Copiarlos desde forms_reports/dist/scripts/. Este orquestador no edita Machines, JDBC ni Coherence: el Admin ya está corriendo y es el único que escribe el dominio (helpers en scripts/admin/, montados en el contenedor Forms).

Desmarca el reequilibrio y deja máximo 100. Con una instancia que no cabe dos tareas, máximo > 100 bloquea el deploy.

Si las dos instancias son del mismo tipo, fija attribute:ecs.instance-id == i-… de wls_reports_ec2 para que no aterrice en la de Forms.

4.4 · Si Create falla por CloudFormation

Un intento fallido deja la pila ECS-Console-V2-Service-wls_reports-ec2-forms-reports-ec2-… en CREATE_FAILED / ROLLBACK_COMPLETE.

  1. CloudFormation → Stacks, región us-east-1, busca wls_reports.
  2. Delete de esa pila (no la de wls_forms-ec2).
  3. Espera DELETE_COMPLETE y vuelve a Create service.

4.5 · Comprobar el servicio

  • Tarea RUNNING en la instancia wls_reports_ec2.
  • getent hosts weblogic-reports.forms.local resuelve la ENI de esta tarea.

5 Arrancar WLS_REPORTS

Primero Admin + WLS_FORMS en RUNNING (forms-ec2 · paso 5). Este script no toca config.xml ni JDBC.

5.1 · Preflight (este contenedor)

curl -s $ECS_CONTAINER_METADATA_URI_V4/task | grep -o '"ServiceName":"[^"]*"'
ip -o -4 addr show scope global | awk '{print $4}'
echo -n "admin_dns="; getent hosts weblogic-admin.forms.local
echo -n "reports_dns="; getent hosts weblogic-reports.forms.local
timeout 5 bash -c 'echo >/dev/tcp/weblogic-admin.forms.local/7001' && echo Admin_OK || echo Admin_FAIL

Debe verse ServiceName":"wls_reports-ec2", reports_dns = la IPv4 de esta ENI, admin_dns = la ENI actual de Forms y Admin_OK. Si Cloud Map de Reports apunta a otra IP, no arranques.

5.2 · UDP 7574 en forms-sg-ecs

Reports se une a Coherence en weblogic-admin.forms.local:7574 (WKA del Admin; Reports no está en esa lista). El protocolo del cluster es UDP. TCP 7574 puede responder y aun así el join falla.

En EC2 → Security Groups → forms-sg-ecs → Inbound: Todos los UDP, origen el propio SG (sg-0e1787d32bac71fcd). Tabla completa: forms-ec2 · 4.6. Se guarda con los servicios arriba; no relances las tareas.

Comprobación (TCP solo confirma el SG de TCP; Coherence sigue necesitando UDP): 

# En Reports:
timeout 3 bash -c 'echo >/dev/tcp/weblogic-admin.forms.local/7574' && echo TCP_7574_OK || echo TCP_7574_FAIL

# En Forms:
ss -lun | grep 7574; ss -ltn | grep 7574
Síntoma si falta UDP El log de Reports repite Delaying formation of a new cluster; waiting for well-known nodes contra weblogic-admin.forms.local/10.x.x.x:7574. A ~5 min: BEA-2194507 / RequestTimeoutException y estado FAILED.

7 Capacidad de reportes concurrentes

Proyección para el servicio wls_reports-ec2 (WLS_REPORTS + colas) con la task definition actual (~3 vCPU y ~15 GiB) y maxEngine="4" en rwserver.conf. Medición del 2/11/2026 con 8 llamadas paralelas a CARR30015.rdf (PDF ligero, ~200 KB). No es comparable a los 100 usuarios de Forms: aquí el número es trabajos a la vez y reportes por minuto.

Número a comunicar Este servidor atiende 4 reportes a la vez. De un RDF ligero como CARR30015: 40–50 por minuto. No comprometer más de 4 simultáneos ni extrapolar a reportes pesados.
4
Reportes a la vez (maxEngine)
40–50 / min
Ritmo de este RDF (primer golpe)
1,9 / 15 GB
Memoria usada / asignada (pico)

7.1 · Qué significa cada número

Escenario Número Qué representa Se puede comprometer
Operación diaria 4 a la vez PDF o RDF corriendo en paralelo; el resto espera en cola Sí — cifra de certificación
Este reporte ligero 40 a 50 / min CARR30015 ~200 KB; 8 PDF en 10 s (motores en frío) Sí, solo para este RDF
Pico en caliente ~80 / min Los 4 motores ya creados; no hay segunda tanda medida Orientativo — no comprometer
Solo si contara la memoria 8+ a la vez RAM ~1,9 GB de 15 GB; el procesador y las colas no aguantan No — no usar este número
1 motor (antes) 25/min
Operación diaria 48/min
Pico en caliente 80/min

Escala 0–100 reportes/minuto del RDF de prueba. El pico en caliente es proyección (4 motores × ~20/min). Antes: maxEngine=1, último de 8 PDF en 16 s.

7.2 · Cómo se llegó a la cifra

Con maxEngine=1 las 8 URLs en paralelo salían en escalera (~2,5 s de trabajo + espera): el último PDF tardaba 16 s. Tras subir rwEng a maxEngine="4" y reiniciar solo WLS_REPORTS, el monitor llegó a 4 procesos oracle.reports.engine.RWEngine (~250 MB cada uno) y el último PDF bajó a 10 s (8 trabajos en 10 s → ~48/min). El cgroup pasó de 1,28 GB en reposo a 1,89 GB en pico. El primer golpe crea las JVM extra (~4 s); por eso el ritmo en frío es menor que el teórico en caliente.

El tope de simultáneos lo pone rwserver.conf, no la RAM. Las colas (CARC00100) comparten este contenedor: no subir a 8 motores sin un RDF pesado y sin medir CPU. Archivo: $DOMAIN_HOME/config/fmwconfig/servers/WLS_REPORTS/applications/reports_14.1.2/configuration/rwserver.conf. 

# En wls_reports-ec2
pgrep -cf 'oracle.reports.engine.RWEngine'
awk '{printf "cgroup=%.2f GB\n", $1/1024/1024/1024}' /sys/fs/cgroup/memory.current

# En el laptop (VPN a la ENI :9012)
./load-reports-cliente.sh -p

★ Lecciones de esta creación

  • Misma AMI y mismo user-data ECS_CLUSTER=forms-reports-ec2 que Forms; no se crea otro cluster.
  • La TD debe caber en wls_reports_ec2 (revisa reports-ec2.json).
  • startReports_EC2.sh es el orquestador; no edita Machines, JDBC ni Coherence. JDBC vive en scripts/admin/ y solo lo aplica el Admin.
  • ADMIN_SERVER_HOST=weblogic-admin.forms.local, no localhost. Arranca solo con Admin + Forms ya RUNNING.
  • Preflight: ServiceName=wls_reports-ec2, ENI (ip, no hostname) = weblogic-reports, weblogic-admin = IP actual de Forms, Admin_OK.
  • Cloud Map weblogic-reports: reutilizar si existe, crear si no. La IP debe ser la de esta tarea, no la de un deploy anterior.
  • Reports no entra al WKA. Se une al WKA del Admin por UDP 7574. El SG necesita Todos los UDP desde sí mismo; “Todos los TCP” no basta. TCP 7574 OK no prueba el cluster. Ver paso 5.2.
  • BEA-2194507 / FAILED: abre UDP (se puede con los servicios arriba) y relanza solo Reports. No toques Forms.
  • Una IP vieja de weblogic-reports en Cloud Map no debe usarse como WKA (Forms no la incluye); sí desvía las colas si getent no coincide con esta ENI.
  • SSH/Instance Connect falla: Session Manager + ecsInstanceRole.
  • execute-command lento: no crees endpoints otra vez; usa los de la VPC documentados en forms-ec2 · paso 6.
  • Capacidad a comunicar: 4 reportes a la vez, 40–50/min de un RDF ligero. El tope es maxEngine (hoy 4), no la RAM. Ver paso 7.
