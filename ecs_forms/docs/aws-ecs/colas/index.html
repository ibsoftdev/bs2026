AWS ECS · Fargate Crear el contenedor Colas Task definition · Servicio · Pro*C · CARC00100

colas-server en el cluster forms_report — contenedor de aplicativo, no Managed Server WebLogic

Contenedor de aplicativo

Visión general

Guía paso a paso para crear la task definition colas-server y su servicio en el cluster forms_report. El contenedor ejecuta procesos de colas Pro*C (por ejemplo CARC00100), monta el dominio y las aplicaciones compartidas en EFS, y usa scripts desde scripts/colas. No arranca WLS_REPORTS ni un Node Manager: Reports ya corre en el servicio Contenedor Reports (weblogic-reports.forms.local:9012) o se accede al mismo EFS de salida (reports_app, rep).

La estructura replica la de la guía de Reports (task definition, servicio, Cloud Map, verificación y ECS Exec), adaptada a un contenedor sin puertos publicados y con comando sleep infinity. Infraestructura común: AdminServer, red, EFS y namespace forms.local.

Colas en Fargate: EFS compartido, Reports por HTTP y validación en app-rector.

2 Crear servicio + Service DiscoveryPendiente

Mismo flujo que Reports 2 y Admin 4: un servicio con una tarea, ECS Exec habilitado, despliegue acumulativo y registro DNS en forms.local.

2.1 · Crear el servicio ECS

  1. Cluster forms_report → Servicios → Crear.
  2. Familia colas-server (revisión más reciente); nombre del servicio colas; tareas deseadas 1.
  3. Capacidad FARGATE, plataforma LATEST, ECS Exec activado.
  4. Implementación: actualización acumulativa, mín. 0 % / máx. 200 % (evita dos procesadores de cola compitiendo por la misma cola en BD).

2.2 · Service Discovery weblogic-colas

CampoValor
NamespaceExistente: forms.local
Nombre del servicio DNSweblogic-colas (FQDN: weblogic-colas.forms.local)
RegistroA, TTL 15, propagación de estado ECS
Se usa colas en lugar del prefijo weblogic-* porque este contenedor no es un Managed Server WebLogic. El nombre sirve para operación, scripts y auditoría; la resolución de Reports sigue siendo weblogic-reports.forms.local.

2.3 · Red del servicio

Igual que admin, Forms y Reports: subred pub-A, security group forms-sg-ecs, IP pública asignada (Admin 4.9). No es necesario mapear puertos en la definición de tarea ni añadir reglas de entrada públicas específicas para Colas.

2.4 · Crear e implementar

Confirmar Service Discovery antes de finalizar el asistente. Tras crear, esperar 1/1 tareas en ejecución.

3 Verificar Running, Cloud Map y ECS ExecPendiente

Comprobar tarea en Ejecutando, instancia en Cloud Map y acceso interactivo (como Reports 3).

aws ecs execute-command \
  --cluster forms_report \
  --task <TASK_ID> \
  --container colas-server \
  --interactive \
  --command "su -s /bin/bash oracle"
df -h | grep -E 'domains|apps|scripts'
ls -la /u01/oracle/scripts

getent hosts weblogic-colas.forms.local weblogic-reports.forms.local weblogic-admin.forms.local
ip -4 -o addr show | awk '{print $2,$4}'

timeout 5 bash -c 'echo >/dev/tcp/weblogic-admin.forms.local/7001' && echo Admin_OK || echo Admin_FAIL
timeout 5 bash -c 'echo >/dev/tcp/weblogic-reports.forms.local/9012' && echo Reports_OK || echo Reports_FAIL
La IP de weblogic-colas.forms.local debe coincidir con la IP privada VPC de la tarea (interfaz eth1), no con direcciones link-local de metadata.

5 Preparar ambiente de colasPendiente

A diferencia de Reports (Paso 5 — Node Manager y WLS_REPORTS), aquí se prepara el entorno Pro*C y batch. Detalle funcional y parámetros de CARC00100 en app-rector · 2.2.

5.1 · Cargar set_batch_env.sh

Desde ECS Exec como oracle, en el directorio de aplicaciones:

cd /u01/oracle/user_projects/apps/proc_app/bin
source ../../set_batch_env.sh
echo "PATH=$PATH"
echo "TWO_TASK=$TWO_TASK"
which CARC00100 LP.sh 2>/dev/null

El script debe dejar en el PATH tanto proc_app/bin como utilidades de Reports del dominio montado.

5.2 · Verificar Oracle y credenciales batch

echo "$TNS_ADMIN"
sqlplus -L /nolog <<'EOF'
connect batch_user/<clave>@SEGU
select sysdate from dual;
exit
EOF

PASS_FILE apunta a USUARIOBATCH.lis según la TD; alinear con el procedimiento operativo de colas.

5.3 · Ejecutar cola (ejemplo)

No se inicia WebLogic en este contenedor. Lanzar el procesador de cola en primer plano o con nohup:

mkdir -p /u01/oracle/user_projects/apps/colas_app/log
cd /u01/oracle/user_projects/apps/proc_app/bin
source ../../set_batch_env.sh

./CARC00100 Y weblogic-colas.forms.local SEGU SEGU \
  >> /u01/oracle/user_projects/apps/colas_app/log/COLA_Y.log 2>&1

Para ejecución continua en background, ver el bloque nohup stdbuf en RECTOR 2.2.

LP.sh: en entornos DEV puede estar configurado para registrar en colas_app/log/LP.log sin imprimir; revisar app-rector antes de esperar PDF inmediato.

6 Validar acceso a Reports y EFS de salidaPendiente

Colas consume Reports de dos formas: HTTP hacia el servicio WebLogic ya desplegado, o archivos compartidos bajo reports_app / rep en el mismo EFS. La prueba PDF vía rwservlet documentada en Reports no es el objetivo principal de esta guía; usar RECTOR 2.2.4 cuando haga falta validar el motor Reports.

6.1 · Conectividad a Reports (HTTP)

curl -s -o /dev/null -w '%{http_code}\n' \
  'http://weblogic-reports.forms.local:9012/reports/rwservlet/getjobid' || true

Código 200 o respuesta esperada del servlet indica que Reports es alcanzable desde Colas (requiere WLS_REPORTS RUNNING — Reports 5.3).

6.2 · Salidas en EFS

ls -la /u01/oracle/user_projects/apps/reports_app 2>/dev/null | head
ls -la /u01/oracle/user_projects/apps/rep 2>/dev/null | head
tail -20 /u01/oracle/user_projects/apps/colas_app/log/LP.log 2>/dev/null

6.3 · Validación funcional CARC00100

Tras procesar órdenes en cola, revisar COLA_*.log, tablas de cola en Oracle y — si aplica impresión — entradas en LP.log. Criterios completos en app-rector · Ejecución de CARC00100.

Anexo Comandos AWS CLIReferencia

Infraestructura compartida: anexo CLI de admin. Comandos específicos de Colas (mismos IDs de red que Reports cuando aplica):

1 · Registrar la task definition

aws ecs register-task-definition \
  --cli-input-json file://aws-ecs/colas/colas.json \
  --region us-east-1

2 · Servicio Cloud Map colas

aws servicediscovery create-service \
  --name colas \
  --namespace-id ns-r3zqawwpjtp5pzue \
  --dns-config 'NamespaceId=ns-r3zqawwpjtp5pzue,RoutingPolicy=MULTIVALUE,DnsRecords=[{Type=A,TTL=15}]' \
  --health-check-custom-config FailureThreshold=1 \
  --region us-east-1 --query 'Service.Arn' --output text

3 · Crear el servicio ECS

aws ecs create-service \
  --cluster forms_report \
  --service-name colas \
  --task-definition colas-server \
  --desired-count 1 \
  --launch-type FARGATE \
  --platform-version LATEST \
  --enable-execute-command \
  --deployment-configuration 'minimumHealthyPercent=0,maximumPercent=200' \
  --network-configuration 'awsvpcConfiguration={subnets=[subnet-01212efd4a9ce759b],securityGroups=[sg-0e1787d32bac71fcd],assignPublicIp=ENABLED}' \
  --service-registries 'registryArn=<ARN_SERVICIO_CLOUDMAP_COLAS>' \
  --region us-east-1

4 · Tarea, diagnóstico y logs

TASK_ARN=$(aws ecs list-tasks --cluster forms_report --service-name colas \
  --region us-east-1 --query 'taskArns[0]' --output text)

aws ecs describe-tasks --cluster forms_report --tasks "$TASK_ARN" --region us-east-1 \
  --query 'tasks[0].{status:lastStatus,stopped:stoppedReason,container:containers[0].reason}'

aws logs tail /ecs/colas-server --follow --region us-east-1

★ Lecciones críticas

Lecciones de infraestructura: admin y Forms. Lecciones de Reports (Motif, log group, Coherence) aplican al servicio Reports, no a Colas. Específicas de Colas:

  1. No es WebLogic — sleep infinity no implica RUNNING de ningún managed server; validar Reports por separado.
  2. Sin portMappings — el servicio no publica HTTP; la conectividad es saliente hacia weblogic-reports:9012 y Oracle.
  3. scripts/colas en EFS — obligatorio antes del primer arranque; mismo patrón de error NFS que scripts/reports.
  4. set_batch_env.sh — sin cargarlo, CARC00100 no encuentra reports/bin ni proc_app/bin.
  5. Un procesador por cola — no escalar desired-count > 1 para la misma cola BD sin partición explícita.
  6. MANAGED_SERVER_* en env — referencia al Reports remoto; no ejecutar startWLSReports.sh aquí salvo error de diseño.
  7. Log group /ecs/colas-server — crear manualmente si CreateLogGroup falla (Reports 1.7).
  8. Imagen r3 — debe incluir cliente Oracle/Pro*C y dependencias de Reports client; alinear con la línea de imagen documentada en admin/Reports.
  9. Validación funcional — seguir RECTOR 2.2 (CARC00100) y 2.2.4 (Reports), no duplicar pruebas rwservlet como objetivo de esta guía.
  10. Secretos — ADMIN_PASSWORD en claro en colas.json es solo DEV; usar Secrets Manager en producción.
