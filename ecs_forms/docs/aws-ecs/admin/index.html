forms-admin sobre el cluster forms_report: la base que usan Forms y Reports

Visión general

Guía paso a paso para preparar la infraestructura en AWS (imagen en ECR, cluster forms_report, EFS rector-dev, security groups y rol de tarea) y crear la task definition forms-admin y su servicio, registrado en Cloud Map como weblogic-admin.forms.local.

Es el primer contenedor que se despliega: aloja el AdminServer y el Node Manager de AdminServerMachine del dominio forms_domain en EFS. Los servicios Forms y Reports reutilizan todo lo que se crea aquí.

Estado del documento: la estructura y los valores provienen de la task definition real forms-admin (revisiones :5/:6). Capturas de la task definition: hechas; servicio y verificación: pendientes.

1 Configuraciones comunes del DominioHecho

Antes de crear el cluster y la task definition, dejar listas las piezas compartidas por los tres contenedores (admin, forms y reports): la imagen en ECR, el security group de las tareas, el EFS del dominio, el rol de tarea para ECS Exec y el namespace Cloud Map forms.local.

1.1 · Imagen en ECRPendiente

Subir a ECR la imagen construida en la fase Crear la imagen. Los tres servicios (admin, forms, reports) usan la misma imagen. 

aws ecr get-login-password --region us-east-1 \
  | docker login --username AWS --password-stdin 730335573515.dkr.ecr.us-east-1.amazonaws.com

docker tag <imagen-local>:<tag> 730335573515.dkr.ecr.us-east-1.amazonaws.com/forms-docker:<tag>
docker push 730335573515.dkr.ecr.us-east-1.amazonaws.com/forms-docker:<tag>

Anotar el digest (sha256:…) resultante; la task definition lo referencia por digest.

1.4 · Rol de tarea para ECS Exec

ECS Exec exige un rol de tarea. El rol de ejecución solo descarga la imagen y escribe logs; el rol de tarea es el que permite execute-command.

1.4a · IAM → Roles

IAM → Roles → Crear rol.

1.4b · Entidad de confianza

  1. Tipo de entidad: Servicio de AWS
  2. Servicio o caso de uso: Elastic Container Service
  3. Caso de uso: Elastic Container Service Task (no “EC2 Role for Elastic Container Service”)
  4. Siguiente

1.4c · Permisos (ssmmessages)

En este paso se puede continuar sin políticas administradas y, tras crear el rol, agregar una política en línea mínima para ECS Exec: 

{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "ssmmessages:CreateControlChannel",
      "ssmmessages:CreateDataChannel",
      "ssmmessages:OpenControlChannel",
      "ssmmessages:OpenDataChannel"
    ],
    "Resource": "*"
  }]
}

En Agregar permisos: dejar Usar política existente, no marcar ninguna política administrada y pulsar Siguiente. La política ssmmessages se agrega después como política insertada (o elegir Crear política insertada en esta misma pantalla).

5 Verificar Running y ECS ExecPendiente

La primera descarga de la imagen tarda ~5 min. Cuando la tarea esté en Ejecutando, entrar con ECS Exec (requiere el session-manager-plugin instalado en la máquina local): 

aws ecs execute-command \
  --cluster forms_report \
  --task <TASK_ID> \
  --container admin \
  --interactive \
  --command "/bin/bash"

Dentro del contenedor:

df -h | grep -E 'domains|apps|scripts'
ls /u01/oracle/scripts
ls /u01/oracle/user_projects/domains
getent hosts weblogic-admin.forms.local   # debe devolver la IP VPC de la tarea

su - oracle

Tarea ECS en Running no significa AdminServer en RUNNING: revisar siempre el log de WebLogic.

★ Lecciones críticas

Errores encontrados al crear el servicio, en el orden en que aparecieron:

  1. ECS Exec sin rol de tarea (Paso 1.4) — el servicio no permite activar Exec; crear ecs-forms-admin-task-role y una nueva revisión.
  2. Timeout hacia ECR (Pasos 1.2 y 4.9) — GetAuthorizationToken … i/o timeout: subnet sin salida a internet o SG default sin egress. Usar solo pub-A, IP pública y forms-sg-ecs.
  3. Espacio efímero (Paso 3.6) — no space left on device al extraer la imagen; subir a 100 GiB.
  4. EFS NFS 2049 (Paso 1.3) — mount.nfs4: Connection timed out: el SG del EFS debe aceptar 2049 desde forms-sg-ecs.
  5. Rutas EFS (Paso 3.6–3.7) — No such file or directory: rootDirectory sin el prefijo erróneo /domain.
  6. Comando sleep infinity (Paso 3.5) — permite ECS Exec y arranque manual; no redefinir PATH.
  7. Service Discovery (Paso 4.6) — solo al crear el servicio; requiere el namespace del Paso 1.5; los demás contenedores dependen de weblogic-admin.forms.local.
  8. Solo pub-A + ruta BD (Paso 4.9–4.10) — no asociar database-A; 192.168.229.137/32 → pcx en Pub-RT.
  9. Hostnames (Paso 7) — sin FQDN en config.xml y nodemanager.properties aparece UnknownHostException.
  10. ECS Running ≠ WebLogic RUNNING (Paso 6) — validar siempre el log del AdminServer.
