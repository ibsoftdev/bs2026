AdminServer y WLS_FORMS en un contenedor, dominio compartido en EFS

Visión general

Esta guía crea el contenedor AdminServer-WLS_FORMS (servicio wls_forms-ec2) en el cluster forms-reports-ec2. La capacidad es una instancia EC2 propia. El contenedor arranca AdminServer y WLS_FORMS con startAdmin_Forms_EC2.sh: alinea las Machines y el WKA de Coherence, levanta un solo Node Manager y no arranca Reports. Reports + Colas van en wls_reports-ec2.

Misma imagen ECR y mismo EFS; el cómputo es EC2.

1 Crear la instancia EC2

La instancia es el host Docker donde ECS coloca la tarea. No se monta EFS en el asistente de EC2: el EFS lo monta la task definition dentro del contenedor.

1.1 · De dónde sale la AMI (imprescindible)

La AMI no está en Quick Start, ni en Marketplace, ni se encuentra bien por nombre en Community AMIs. Hay que tomar el ID oficial del Parameter Store público de ECS y lanzar desde esa AMI.

  1. Systems Manager → Parameter Store.
  2. Marca Públicos (no los parámetros de la cuenta).
  3. Abre exactamente: /aws/service/ecs/optimized-ami/amazon-linux-2023/recommended/image_id
  4. Copia el valor (un ami-…). Ese ID cambia cuando AWS publica una AMI nueva.
  5. EC2 → Images → AMIs → filtro Public images → pega el ID.
  6. Selecciona la AMI (nombre tipo al2023-ami-ecs-hvm-2023.0.…) → Launch instance from AMI.
No uses otra imagen Amazon Linux “normal”, Ubuntu o una AMI de Marketplace no traen el agente ECS. La instancia nunca aparecerá en la pestaña Infraestructura del cluster.
Por qué este camino En el asistente Launch instance, Quick Start no lista la AMI ECS-optimized de AL2023. Buscar el ID en Community AMIs también falla. Parameter Store → AMI pública → Launch from AMI es la ruta que funciona.

1.3 · Rol ecsInstanceRole

No reutilices el rol de tarea (ecs-forms-admin-task-role). El perfil de instancia necesita confianza ec2.amazonaws.com y estas políticas:

  • AmazonEC2ContainerServiceforEC2Role — el agente registra la instancia en el cluster
  • AmazonSSMManagedInstanceCore — Session Manager (el SG no abre SSH 22)

1.4 · User-data (cluster al que se une)

Sin esta línea la instancia arranca pero no entra en ningún cluster. 

#!/bin/bash
echo ECS_CLUSTER=forms-reports-ec2 >> /etc/ecs/ecs.config
Nombre exacto Tiene que coincidir con el cluster del paso 2. Si el nombre está mal, la instancia no aparece en Infraestructura de forms-reports-ec2.

2.2 · Las instancias deben verse en Infraestructura

Un cluster “creado” con 0 instancias no sirve para un servicio EC2. La tarea queda PENDING sin capacidad.

  1. ECS → cluster forms-reports-ec2 → pestaña Infraestructura.
  2. Debes ver wls_forms_ec2 (y la de Reports, si ya la lanzaste) en estado ACTIVE.
  3. CPU/memoria libre deben alcanzar lo que pide la TD.
Criterio de listo Cluster Active + al menos la instancia Forms ACTIVE en Infraestructura. Si esa pestaña dice “No hay instancias de contenedor”, no crees el servicio.

3.3 · Scripts en EFS

El orquestador startAdmin_Forms_EC2.sh llama a admin/startAdminserver.sh y forms/startWLSForms.sh. JDBC/TNS del dominio compartido viven junto al Admin (scripts/admin/), no en scripts/common/. Deben existir en EFS antes del arranque en frío:

  • /u01/oracle/scripts/startAdmin_Forms_EC2.sh
  • /u01/oracle/scripts/admin/startAdminserver.sh
  • /u01/oracle/scripts/admin/set-db-jdbc-url.sh
  • /u01/oracle/scripts/admin/set-db-tnsnames.sh

Copiarlos desde forms_reports/dist/scripts/. En EFS borra scripts/common/ si quedó de un intento anterior.

startAdminserver.sh busca los helpers en este orden: el directorio del propio script, /u01/oracle/scripts/admin y /u01/oracle/scripts (en Fargate el montaje de admin/ cae en esa ruta). Los aplica una sola vez en el arranque en frío del Admin, con los servidores abajo. Forms y Reports no reescriben JDBC. El orquestador arranca Forms con RCU_DB_SKIP=1 porque el Admin ya aplicó la URL.

No reescribir JDBC con Admin vivo Si una copia vieja de startWLSForms.sh en EFS llama a set-db-jdbc-url.sh con el Admin arriba, falla. Arranque puntual: RCU_DB_SKIP=1 /u01/oracle/scripts/forms/startWLSForms.sh. No relances el orquestador si Admin ya está RUNNING: no edita config.xml con un weblogic.Name= en marcha.

4.2 · Reequilibrio de AZ y máximo 100

Con reequilibrio activo, ECS exige máximo > 100. En una sola subnet y una instancia que no cabe dos tareas, eso bloquea el deploy. Desmarca el reequilibrio y deja máximo 100.

4.3 · Placement (opcional)

En este layout no hace falta si la instancia de Forms es la única que cabe la TD. Si hay dos instancias iguales, añade attribute:ecs.instance-id == i-… de wls_forms_ec2.

4.4 · Si Create falla por CloudFormation

Un intento fallido deja la pila ECS-Console-V2-Service-wls_forms-ec2-forms-reports-ec2-… en CREATE_FAILED / ROLLBACK_COMPLETE. ECS no reutiliza el nombre hasta borrarla.

  1. CloudFormation → Stacks, región us-east-1, filtro Active, busca ECS-Console o wls_forms.
  2. Delete de esa pila (no las de forms-reports, admin o forms).
  3. Espera DELETE_COMPLETE y vuelve a Create service.

4.5 · Comprobar el servicio

  • Tarea RUNNING en la instancia wls_forms_ec2.
  • getent hosts weblogic-admin.forms.local resuelve la ENI de esta tarea (no una IP de un deploy anterior).

La imagen no trae hostname. Usa ip. Ignora 169.254.172.x (enlace local de ECS). La IPv4 10.171.240.x/… debe coincidir con Cloud Map.

4.6 · Security group forms-sg-ecs

Las dos tareas (wls_forms-ec2 y wls_reports-ec2) usan forms-sg-ecs (sg-0e1787d32bac71fcd). Coherence une el cluster por UDP 7574, no por TCP. “Todos los TCP” entre el SG y sí mismo no alcanza.

TipoPuertoOrigenUso
TCP70010.0.0.0/0 (DEV)Admin HTTP
TCP90010.0.0.0/0 (DEV)Forms HTTP
TCP90120.0.0.0/0 (DEV)Reports HTTP
Todos los TCP0–65535el propio forms-sg-ecsNM, t3, managed

Se edita con los servicios arriba La regla aplica a las ENI enseguida. No relances las tareas para abrir UDP. Si falta, Reports queda en Delaying formation of a new cluster y a ~5 min pasa a FAILED (BEA-2194507). Ver reports-ec2 · 5.2.

5 Arrancar AdminServer y WLS_FORMS

Arranque en frío: Admin, Forms y Reports abajo en todos los contenedores. El script no edita config.xml si hay un weblogic.Name=. 

pgrep -af 'weblogic.Name='
ls -l /u01/oracle/scripts/startAdmin_Forms_EC2.sh \
      /u01/oracle/scripts/admin/set-db-jdbc-url.sh \
      /u01/oracle/scripts/admin/set-db-tnsnames.sh
/u01/oracle/scripts/startAdmin_Forms_EC2.sh

El orquestador aplica Machines + WKA, arranca el Admin (setsid nohup startAdminserver.sh -keep, sesión propia) y luego Forms con RCU_DB_SKIP=1. Cerrar ECS Exec ya no manda SIGTERM al JVM (BEA-000388). En el bloque 0/2 Machines debe quedar:

  • AdminServerMachine y FormsMachine → weblogic-admin.forms.local
  • WKA de Coherence solo con ese host (Reports no entra; si entra una IP muerta, Forms no pasa a RUNNING)
  • Un solo Node Manager (puerto 5556)
WKA y Reports REPORTS_MACHINE_HOST se escribe en ReportsMachine para el Node Manager. No se mete al WKA de Coherence desde este script: Forms formaría cluster esperando weblogic-reports.forms.local:7574. Reports se une después, cuando wls_reports-ec2 esté arriba, contactando este WKA por UDP 7574.

5.1 · Si el Admin ya está RUNNING

No relances startAdmin_Forms_EC2.sh. Si Forms no subió (p. ej. JDBC con Admin vivo), solo Forms: 

RCU_DB_SKIP=1 /u01/oracle/scripts/forms/startWLSForms.sh
Criterio de listo Admin en localhost:7001, WLS_FORMS en RUNNING, http://localhost:9001/forms/frmservlet responde. Coherence en este host: ss -lun | grep 7574 (UDP en 0.0.0.0:7574) y TCP 7574 en la ENI.

6 Endpoints VPC para ECS Exec

En Fargate la tarea tenía IP pública y aws ecs execute-command llegaba a SSM por Internet en segundos. En EC2 + awsvpc la ENI de la tarea es solo privada (assignPublicIp no aplica). Sin NAT, cada API de AWS que resuelva a una IP pública (13., 44., 3.) espera el timeout y la sesión tarda 30–60 s.

Estos endpoints son de la VPC (valen para Forms y Reports). Se crean una vez. No hace falta redesplegar las tareas.

getent hosts sts.us-east-1.amazonaws.com logs.us-east-1.amazonaws.com \
  ssmmessages.us-east-1.amazonaws.com ssm.us-east-1.amazonaws.com \
  ec2messages.us-east-1.amazonaws.com
time timeout 5 bash -c 'echo >/dev/tcp/sts.us-east-1.amazonaws.com/443' && echo sts_ok
time timeout 5 bash -c 'echo >/dev/tcp/logs.us-east-1.amazonaws.com/443' && echo logs_ok

Criterio: las cinco en 10.171.240.x y OK en milisegundos. IPs 13. / 44. / 3. + timeout 5 = FAIL significan que ese API todavía sale a Internet.

6.4 · Sesión nueva

Cierra la sesión vieja. El agente no reutiliza el DNS anterior. 

time aws ecs execute-command \
  --cluster forms-reports-ec2 \
  --task <TASK_ID> \
  --container wls_forms-ec2 \
  --interactive --region us-east-1 \
  --command "bash"
Criterio de listo El prompt aparece en pocos segundos (como en Fargate). Dentro, su - oracle si hace falta. No pongas su en el --command (PAM puede colgar el plugin).

★ Lecciones de esta creación

  • La AMI ECS-optimized se obtiene del Parameter Store público, no del catálogo Quick Start.
  • El cluster Solo Fargate acepta EC2 si el user-data apunta a su nombre; hay que verlas en Infraestructura.
  • La TD debe caber en la instancia (revisa CPU/memoria de forms-ec2.json).
  • startAdmin_Forms_EC2.sh es el orquestador: Machines + WKA, Admin desacoplado (setsid nohup … -keep) y Forms con RCU_DB_SKIP=1.
  • JDBC/TNS viven en scripts/admin/. El Admin los aplica una vez en frío. No hay scripts/common/.
  • No relances el orquestador si Admin ya está RUNNING. Forms suelto: RCU_DB_SKIP=1 startWLSForms.sh.
  • BEA-000388 al cerrar Exec era SIGTERM al JVM padre; el setsid lo evita.
  • Cloud Map es weblogic-admin (se reutiliza). No hace falta weblogic-forms. getent debe coincidir con la ENI actual (ip, no hostname).
  • Coherence WKA solo Admin+Forms. Una IP muerta de weblogic-reports deja Forms en STARTING.
  • El SG forms-sg-ecs necesita Todos los UDP desde sí mismo (Coherence 7574). Se puede agregar con las tareas arriba. Ver paso 4.6.
  • SSH/Instance Connect falla: Session Manager + ecsInstanceRole.
  • execute-command lento en EC2: la ENI no tiene IP pública. Faltaban VPC endpoints sts y logs (además de ssmmessages / ssm / ec2messages). Ver paso 6.
