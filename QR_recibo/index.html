Arquitectura Lógica — Token JWT y Código QR

Generación Segura de Recibos

Flujo para emitir recibos en PDF a través de un código QR con token JWT firmado. Solo la aplicación genererar_recibo se expone a Internet; la base de datos y el servidor de reportes permanecen en la red interna.

Origen del QR

PLSQL_QR · JWT

Acceso público

CloudFront · HTTPS

Recursos protegidos

Oracle DB · Reports Server

Resultado

PDF del recibo

◆ Flujo Detallado del Proceso

Recorrido completo desde la generación del código QR hasta la entrega del PDF del recibo al usuario.

1

Lectura de datos (PLSQL_QR)

PLSQL_QR consulta las tablas necesarias en Oracle Database para obtener sucursal, número de recibo, cliente y demás datos del recibo.

2

Construcción del JWT

PLSQL_QR arma el payload del token con los campos del recibo (suc_recibo, nu_recibo, etc.) y lo firma con la clave secreta almacenada en BD.

3

Generación del QR

PLSQL_QR construye la URL https://dominio/genererar_recibo?k=<token> y la codifica en un código QR para impresión o visualización.

4

Escaneo y acceso

El usuario escanea el QR. El navegador abre la URL a través de Internet y Amazon CloudFront enruta la petición a la aplicación Spring Boot.

5

Validación del token

genererar_recibo obtiene la clave secreta de Oracle Database, decodifica el JWT, verifica la firma y confirma que el token es válido y vigente.

6

Generación del reporte

Con los datos del token, la aplicación invoca al Oracle Reports Server en la red interna para generar el PDF del recibo indicado.

7

Entrega del PDF

El PDF consolidado se devuelve como respuesta HTTP al navegador del usuario. El recibo queda disponible sin exponer recursos internos.

◆ Características del Diseño

Resumen orientado a decisión de negocio, detalle técnico y principios de seguridad del flujo.

💼 Visión Ejecutiva

  • ▸ Acceso controlado: El usuario accede al recibo únicamente mediante un código QR con un token de un solo uso o vigencia limitada.
  • ▸ Superficie de ataque reducida: Solo la aplicación genererar_recibo está expuesta a Internet; la BD y el servidor de reportes permanecen protegidos.
  • ▸ Sin credenciales del usuario: No se requiere autenticación adicional; el token JWT actúa como autorización temporal para ese recibo específico.
  • ▸ Distribución global: CloudFront actúa como punto de entrada seguro (HTTPS) ante el dominio público de la empresa.

🛡 Modelo de Seguridad

  • ▸ Token firmado: El JWT incluye los identificadores del recibo y está firmado con una clave secreta que solo reside en la base de datos interna.
  • ▸ Validación en servidor: genererar_recibo verifica firma, integridad y vigencia antes de procesar cualquier solicitud de recibo.
  • ▸ Aislamiento de recursos críticos: Oracle Database y Reports Server no tienen endpoint público; solo genererar_recibo puede comunicarse con ellos.
  • ▸ Principio de mínimo privilegio: El token autoriza únicamente la generación del recibo identificado en su payload, sin acceso a otros datos.

📄 Payload del Token JWT

sub Identificador del sujeto (cliente / póliza)
name Nombre del titular
suc_recibo Código de sucursal del recibo
nu_recibo Número del recibo a generar
iat Timestamp de emisión (validez temporal)
